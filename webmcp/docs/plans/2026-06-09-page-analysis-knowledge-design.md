# Page Analysis And Knowledge Design

## Context

Workflow creation currently collects a browser trace, sends the trace to synthesis, materializes the resulting workflow JSON, then runs or evaluates it. The trace contains URL, title, page text, and screenshots, but the system does not persist reusable page structure analysis or general script-generation lessons.

## Approaches Considered

1. Store analysis and knowledge in the existing workflow SQLite DB.
   This keeps creation sessions, attempts, trace artifacts, analysis, and reusable knowledge in one query boundary. It is the recommended approach because `--db` already identifies the durable workflow store.

2. Store analysis in a separate SQLite DB.
   This reduces schema coupling, but every CLI and Desktop caller would need a second path and migration lifecycle. It also makes creation-session debugging harder.

3. Store analysis as JSONL files beside run artifacts.
   This is simple for append-only logs, but weak for URL lookups, updates, and prompt-time retrieval.

## Selected Design

Extend `WorkflowSkillStore.initialize()` with two persistent areas:

- `page_analyses`: one row per normalized URL key, with original URL, title, framework hints, frame summary, locator notes, analysis JSON, evidence JSON, and update counters.
- `workflow_knowledge_entries`: append-style lessons that are not URL-scoped, with category, summary, content JSON, source, confidence, tags, and timestamps.

URL keys are generated by a shared utility that removes query/fragment, normalizes host casing, strips common default ports, and converts the host/path into kebab-case. The same utility is used on insert and lookup.

## Data Flow

`create-workflow` collects an `ArtifactTrace`. Immediately after trace collection, Core derives a lightweight page analysis from trace metadata and page text, upserts it by normalized URL key, then reads the latest matching page analysis plus recent relevant knowledge entries. The trace is enriched with this reusable context before synthesis prompt construction. When creation succeeds or fails, Core appends a knowledge entry describing the outcome, so repeated tool-generation sessions accumulate lessons over time.

## Testing

Use deterministic static traces for at least three URLs:

- a query-heavy page URL to prove key normalization removes query strings,
- an iframe-heavy page text fixture to prove frame hints are captured,
- a framework-heavy page text fixture to prove framework hints and knowledge retrieval reach the synthesis prompt.

The tests should verify stored rows, lookup by query variants, prompt context, and creation-runtime continuous updates.
