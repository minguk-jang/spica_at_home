# JSON 대시보드 구현 계획

> 저장된 JSON 파일을 불러와서 관리/수정/이동할 수 있는 대시보드 기능

---

## 1. 요구사항 정리

### 핵심 기능
1. **JSON 파일 로드**: 설정된 디렉토리에서 `selectors-*.json` 파일 자동 스캔
2. **대시보드 뷰**: 모든 JSON 파일 목록을 카드/리스트로 확인
3. **상세 편집**: 각 JSON 파일의 entry를 클릭하여 셀렉터 값 및 메타데이터 수정
4. **파일 간 이동**: 드래그 앤 드롭으로 entry를 한 JSON에서 다른 JSON으로 이동
5. **저장**: 수정사항을 원본 JSON 파일에 반영

### UI 위치
- **별도 페이지** (`dashboard.html`)로 구현
- `chrome-extension://` 내부 페이지로 열려서 넓은 화면 활용 가능
- 사이드패널에서 "대시보드 열기" 버튼으로 진입


## 3. 구현 단계 (Phase별)

### Phase 1: 파일 읽기 인프라 (fs-storage.js 확장)

**목표**: 디렉토리에서 JSON 파일 목록 가져오기 및 읽기

**추가할 함수들:**

| 함수 | 설명 |
|------|------|
| `listJsonFiles()` | 설정된 디렉토리에서 `selectors-*.json` 파일명 목록 반환 |
| `readJson(filename)` | 특정 JSON 파일 읽어서 파싱 후 반환 |
| `deleteFile(filename)` | JSON 파일 삭제 |
| `getDirHandle()` | 현재 dirHandle 반환 (대시보드에서 사용) |

**구현 방식:**
- `dirHandle.values()`로 디렉토리 내 파일 순회
- `FileSystemFileHandle.getFile()` → `file.text()` → `JSON.parse()`
- 기존 `saveJson()`은 그대로 활용 (수정 저장 시)

**리스크:**
- File System Access API는 사이드패널 컨텍스트에서 호출되므로, 대시보드(별도 탭)에서 dirHandle을 공유하려면 IndexedDB를 통해 핸들을 전달해야 함
- 별도 탭에서 `dirHandle.requestPermission()` 재호출 필요할 수 있음 (사용자 제스처 필요)

### Phase 2: 대시보드 메인 화면 (파일 목록)

**목표**: 모든 JSON 파일을 카드 형태로 보여주는 메인 뷰

**UI 레이아웃:**
```
┌────────────────────────────────────────────────────────────┐
│  📊 Selector Dashboard                    [새로고침] [닫기] │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐     │
│  │ 📄 selectors- │  │ 📄 selectors- │  │ 📄 selectors- │     │
│  │ 2026-02-08.. │  │ 2026-02-07.. │  │ 2026-02-06.. │     │
│  │              │  │              │  │              │     │
│  │ 12 entries   │  │ 5 entries    │  │ 8 entries    │     │
│  │ 2.3 KB       │  │ 1.1 KB       │  │ 1.8 KB       │     │
│  │              │  │              │  │              │     │
│  │ [열기] [삭제] │  │ [열기] [삭제] │  │ [열기] [삭제] │     │
│  └──────────────┘  └──────────────┘  └──────────────┘     │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

**카드에 표시할 정보:**
- 파일명 (날짜 부분 파싱해서 읽기 좋게 표시)
- entry 개수 (`totalEntries`)
- 파일 크기
- 내보낸 시간 (`exportedAt`)
- [열기] [삭제] 버튼

**동작:**
- 페이지 로드 시 `FsStorage.listJsonFiles()` 호출
- 권한이 없으면 "디렉토리 접근 허용" 버튼 표시 (사용자 제스처로 `requestPermission`)
- 카드 클릭 또는 [열기] → Phase 3의 상세 뷰로 전환

**목표**: 하나의 JSON 파일 내 entry들을 보여주고 수정 가능

**UI 레이아웃:**

```
│  │ 📌 Element Info                                      │  │
│  │  Tag: button    ID: submit-btn                       │  │
│  │  URL: https://example.com                            │  │
│  │  Time: 2026-02-08 11:30:40                          │  │
│  │  Label: [편집 가능한 라벨/메모 필드]                    │  │
│  ├──────────────────────────────────────────────────────┤  │

│  │  data-testid:[button[data-testid=".."] ✅            │  │

│                                                            │
└────────────────────────────────────────────────────────────┘
```

**편집 가능 항목:**
- **셀렉터 값**: 각 셀렉터(tag, id, classes 등) 텍스트 인라인 편집
- **메타데이터**: 라벨/메모 필드 추가 (elementInfo에 `label` 프로퍼티 추가)
- **elementInfo**: URL, textContent 등 수정 가능

**편집 불가 항목:**
- validation 결과 (읽기 전용, 저장 시 재검증은 하지 않음 — 원래 페이지에서만 검증 가능)

**동작:**
- entry별 아코디언 또는 스크롤 리스트
- 인라인 편집: 셀렉터 값 클릭 시 input으로 전환
- [저장] 클릭 시 `FsStorage.saveJson(filename, modifiedData)` 호출
- [삭제] 시 해당 entry를 배열에서 제거
- [↑][↓] 순서 변경

### Phase 4: 드래그 앤 드롭 (파일 간 entry 이동)

**목표**: 두 JSON 파일을 나란히 보면서 entry를 드래그로 이동

**UI 레이아웃:**
```
┌────────────────────────────────────────────────────────────┐
│  📊 파일 간 이동 모드                          [저장] [닫기] │
├──────────────────────────┬─────────────────────────────────┤
│  📄 selectors-02-08..    │  📄 selectors-02-07..           │
│  [파일 선택 ▼]            │  [파일 선택 ▼]                  │
├──────────────────────────┼─────────────────────────────────┤
│                          │                                 │
│  ≡ Entry 1: <button>     │  ≡ Entry 1: <a>                │
│    #submit-btn           │    .nav-link                    │
│                          │                                 │
│  ≡ Entry 2: <input>      │  ≡ Entry 2: <div>              │
│    #search-box     ──────┼───→ (드래그하여 이동)             │
│                          │                                 │
│  ≡ Entry 3: <div>        │  ≡ Entry 3: <span>             │
│    .container            │    .badge                       │
│                          │                                 │
├──────────────────────────┼─────────────────────────────────┤
│  3 entries               │  3 entries                      │
└──────────────────────────┴─────────────────────────────────┘
```

**구현 방식:**
- HTML5 Drag and Drop API 사용 (네이티브)
- 좌/우 패널에 각각 다른 JSON 파일 로드
- 드래그 시작: `dragstart` → entry 데이터를 `dataTransfer`에 저장
- 드롭 존: 반대편 패널의 entry 리스트
- 드롭 시: 원본에서 제거 + 대상에 추가 (이동) 또는 원본 유지 + 대상에 추가 (복사, Ctrl 키 홀드)
- 드롭 위치에 따라 삽입 순서 결정

**UX 고려사항:**
- 드래그 중 시각적 피드백 (고스트 이미지, 드롭 존 하이라이트)
- 이동 vs 복사 구분 (기본: 이동, Ctrl+드래그: 복사)
- 같은 패널 내에서 드래그로 순서 변경도 지원
- Undo 기능: 실수로 이동한 경우 Ctrl+Z로 되돌리기

---

### Phase 5: 사이드패널 연동

**목표**: 기존 사이드패널에서 대시보드로 진입하는 버튼 추가

**변경 파일:**
- `sidepanel.html`: "대시보드" 버튼 추가
- `sidepanel.js`: 버튼 클릭 시 `chrome.tabs.create({ url: 'dashboard.html' })` 호출
- `background.js`: (필요 시) 대시보드 탭 관리 메시지 추가

**추가 고려:**
- 대시보드가 이미 열려있으면 해당 탭으로 포커스 이동
- 대시보드에서 수정 후 사이드패널의 히스토리가 영향받지 않도록 독립적 운영

## 4. 기술적 고려사항

### File System Access API 제약
- **사용자 제스처 필요**: 대시보드 페이지에서 처음 열 때 "디렉토리 접근 허용" 버튼 클릭 필요
- **IndexedDB 핸들 공유**: `dirHandle`은 사이드패널과 대시보드가 같은 origin이므로 IndexedDB를 통해 공유 가능
- **권한 유지**: 브라우저 재시작 후에는 다시 권한 요청 필요

### 상태 관리
- 대시보드는 자체적으로 파일을 읽고 수정 (사이드패널과 독립)
- 수정 중인 데이터는 메모리에서 관리하다가 [저장] 시 파일에 쓰기
- 미저장 변경사항이 있을 때 페이지 이탈 경고 (`beforeunload`)

### 성능
- 대량 entry가 있는 파일 대비 가상 스크롤 고려 (초기엔 불필요, 100+ entry 시 추후 적용)
- JSON 파일 목록은 캐시하되, [새로고침] 버튼으로 갱신 가능

### 스타일
- 기존 `sidepanel.css`의 GitHub Dark 테마와 동일한 디자인 시스템 적용
- CSS 변수를 공통 파일로 분리하거나, `dashboard.css`에서 동일 변수 재정의

## 5. 구현 순서 요약

| 순서 | Phase | 핵심 작업 | 의존성 |
|------|-------|----------|--------|
| 1 | Phase 1 | `fs-storage.js` 확장 (listJsonFiles, readJson) | 없음 |
| 2 | Phase 2 | `dashboard.html/js/css` 메인 화면 (파일 카드 목록) | Phase 1 |
| 3 | Phase 3 | 상세 편집 뷰 (entry 수정, 삭제, 정렬) | Phase 2 |
| 4 | Phase 4 | 드래그 앤 드롭 (파일 간 이동) | Phase 3 |
| 5 | Phase 5 | 사이드패널 연동 + manifest 업데이트 | Phase 2 |

> Phase 5는 Phase 2 완료 후 바로 진행 가능 (Phase 3, 4와 병렬)

## 6. 리스크 및 대응

| 리스크 | 영향 | 대응 |
|--------|------|------|
| dirHandle 권한이 대시보드 탭에서 만료 | 파일 읽기 실패 | "권한 다시 허용" 버튼 + 안내 메시지 |
| 대시보드에서 파일 수정 중 사이드패널에서도 저장 | 데이터 충돌 | 저장 전 파일 타임스탬프 확인, 충돌 시 경고 |
| 대용량 JSON 파일 (수백 entry) | UI 렉 | 초기엔 심플 렌더링, 추후 가상 스크롤 |
| 드래그 앤 드롭 모바일/터치 미지원 | 접근성 | 터치 이벤트 핸들링은 추후 고려 (데스크톱 우선) |

## 7. 미래 확장 가능성

- **검색/필터**: 대시보드에서 모든 파일을 통합 검색
- **병합**: 여러 JSON 파일을 하나로 합치기
- **분할**: 하나의 JSON 파일을 조건에 따라 분할
- **태그 시스템**: entry에 태그를 달아서 그룹 관리
- **비교 뷰**: 두 entry의 셀렉터 diff 비교
