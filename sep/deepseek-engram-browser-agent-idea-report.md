# DeepSeek Engram 분석 및 브라우저 에이전트 정적 추론 메모리 아이디어 보고서

## 1. 보고 개요

- 작성일: 2026-09-30
- 보고 목적: DeepSeek Engram의 원리를 정리하고, 브라우저 에이전트가 반복해서 수행하는 정적 추론을 저장·조회하는 구조로 옮기는 아이디어를 제안한다.
- 참고 논문: [Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models](https://arxiv.org/abs/2601.07372) (DeepSeek + 베이징 대학교, arXiv:2601.07372)
- 참고 구현: [deepseek-ai/Engram](https://github.com/deepseek-ai/Engram)
- 문서 상태: 아이디어 단계. 아래 적용안은 모두 가설이며 브라우저 에이전트에서의 효과는 검증되지 않았다.

## 2. 한 줄 결론

Engram 구조는 사전학습 단계의 모델 모듈이라 API 기반 에이전트에 직접 붙일 수 없다. 그러나 **"정적 지식은 O(1) 조회로 꺼내고 동적 추론만 LLM에 맡긴다"는 원리**는 에이전트 시스템 계층에서 재현할 수 있다. 핵심은 정규화한 화면·요소 서명을 키로 하는 조회 메모리, 조회 결과를 검증하는 게이트, 실패 시 LLM으로 되돌아가는 폴백이다.

## 3. Engram의 원리

### 3.1 문제의식

- MoE는 조건부 **연산**으로 희소성을 만든다.
- 그러나 Transformer에는 지식 조회 primitive가 없어서 고정 패턴(개체명, 관용구)도 여러 레이어의 연산으로 재구성한다.
- Engram은 조건부 **메모리**라는 두 번째 희소성 축을 추가해 정적 패턴을 N-gram 임베딩 조회로 처리한다.

### 3.2 동작 단계 (토큰 위치별)

| 단계 | 내용 |
|---|---|
| 토크나이저 압축 | NFKC 정규화와 소문자화로 의미가 같은 토큰 ID를 합친다. 128k 어휘가 약 23% 감소한다. |
| 멀티 헤드 해싱 | 2-gram부터 N-gram까지 만들고 K개 해시 함수로 임베딩 테이블을 조회해 concat한다. |
| 문맥 인식 게이팅 | hidden state를 query, 조회 결과를 key/value로 두고 0~1 게이트를 계산한다. 문맥과 맞지 않으면 0에 수렴해 충돌과 다의어 노이즈를 거른다. |
| Depthwise Conv + 잔차 | kernel 4의 경량 conv로 수용 영역을 넓히고 hidden state에 잔차로 더한다. |
| 멀티 브랜치 | 임베딩 테이블과 value 투영은 공유하고 key 투영만 브랜치별로 둔다. |

삽입 위치는 초기 레이어(layer 2)가 최적이었고, layer 2와 6에 함께 넣으면 소폭 더 좋았다.

### 3.3 스케일링 법칙과 결과

- 비활성 파라미터를 MoE 전문가와 Engram 메모리에 나누면 검증 손실이 **U자형**이 된다. 최적점은 MoE 약 75~80%, 메모리 약 20~25%다.
- 백본을 고정하고 메모리 슬롯만 늘리면 추가 FLOPs 없이 손실이 로그-선형으로 계속 감소했다.
- 27B 모델을 MoE와 같은 파라미터·FLOPs로 비교한 결과는 다음과 같다.

| 벤치마크 | MoE-27B | Engram-27B |
|---|---:|---:|
| MMLU | 57.4 | 60.4 |
| BBH | 50.9 | 55.9 |
| HumanEval | 37.8 | 40.8 |
| GSM8K | 58.4 | 60.6 |

- 지식 과제뿐 아니라 추론·코드·수학에서 이득이 더 컸고, Multi-Query NIAH는 84.2%에서 97.0%로 올랐다.
- 참고: 2차 요약에는 MMLU +3.4로 나오지만 논문 본문 표 기준으로는 +3.0이다. 인용 시 원문 표를 확인한다.

### 3.4 효과의 원인

- **유효 깊이 증가**: Engram 모델의 layer j가 MoE의 layer j+5~7과 유사했다. 정적 지식 재구성을 떠넘겨 초기 레이어가 더 깊은 일을 한다.
- **기능 분리**: 추론 시 Engram을 끄면 사실 지식 과제는 29~44%만 남고 독해는 81~93%가 남는다. Engram이 사실 지식의 주 저장소다.
- **시스템 효율**: 조회 주소가 입력 토큰만으로 결정되므로 prefetch가 가능하다. 100B 테이블을 호스트 DRAM에 두어도 오버헤드가 1.9~2.8%였다.

## 4. 브라우저 에이전트에 옮길 수 있는 원리

| Engram | 브라우저 에이전트 대응 |
|---|---|
| 정적 지식을 연산 대신 조회 | 로그인 폼, 쿠키 배너, 페이지네이션 같은 반복 패턴을 LLM 추론 대신 조회 |
| 토크나이저 압축 | 동적 ID, class 해시, 광고 영역을 제거한 DOM 정규화 |
| 멀티 헤드 해싱 | 도메인+골격, 프레임워크 지문+골격, 의미 버킷 등 여러 관점의 키로 조회 |
| 문맥 인식 게이팅 | 요소 존재, URL 패턴, 확신도를 확인한 뒤에만 조회 결과 사용 |
| 결정적 주소 → prefetch | 다음 페이지 메모리를 페이지 로딩·액션 실행 중에 미리 조회 |
| U자형 배분 | 조회 처리 비율 대 성공률·지연·비용 곡선 측정 |

## 5. 정적 추론 메모리 구조 아이디어

### 5.1 저장 대상

LLM이 매번 새로 추론하지만 결과가 거의 같은 것들이다.

- 이 페이지는 로그인 폼이다.
- 이 버튼이 제출 버튼이다.
- 이 모달은 닫아야 한다.
- 이 요소를 누르면 페이지가 이동한다.

이번 태스크에서 무엇을 고를지 같은 동적 추론은 LLM에 남긴다.

### 5.2 3계층 메모리 (Engram의 N-gram 차수에 대응)

| 계층 | 키 | 값 | 예시 |
|---|---|---|---|
| L1 요소 | role + 라벨 + 구조 위치 정규화 서명 | 의미 태그, 부작용 예측 | "장바구니 담기 버튼, 클릭 시 XHR만 발생, 페이지 이동 없음" |
| L2 화면 | 정규화한 DOM 골격 해시 + 도메인 | 페이지 유형, 핵심 영역, 무시 영역 | "상품 상세: 가격·옵션·담기가 핵심, 광고는 무시" |
| L3 흐름 | 직전 N개 (화면, 액션) 시퀀스 해시 | 다음 액션 후보와 확신도 | "검색 결과 → 정렬 클릭 → 낮은 가격순 옵션" |

같은 상황을 K개 관점의 키로 조회하면 사이트 개편으로 한 관점이 깨져도 다른 관점이 적중한다. 프레임워크·템플릿 관점(Shopify, WordPress, 로그인 위젯 등)은 낯선 도메인으로의 전이에도 쓸 수 있다.

### 5.3 쓰기 경로: 실행 궤적에서 증류

```text
LLM이 성공한 궤적 → 스텝별 (화면 상태, 액션, 결과) 기록
  → 정규화 (동적 ID/class 제거, role 기반 서명)
  → "LLM 없이도 같은 액션이 나왔는가" 재현 검증
  → 반복 확인된 것만 승격 (확신도 = 성공 / 시도)
```

실패·우회 궤적은 함정 페이지, 가짜 버튼, 자주 바뀌는 영역에 대한 음의 증거로 저장한다.

### 5.4 읽기 경로: 게이트를 통한 3단 분기

```text
현재 상태 → 정규화 → K개 키로 조회
  → 게이트 (요소 존재, URL 패턴, 확신도, 직전 결과 일치)
     ├ 통과 + 확신도 높음 → 즉시 실행 (LLM 0회)
     ├ 통과 + 확신도 중간 → LLM 프롬프트에 메모리 힌트로 주입
     └ 실패              → 순수 LLM 추론, 결과는 쓰기 경로로 환류
```

실행 후 결과가 예측과 다르면 해당 엔트리의 확신도를 즉시 낮춘다. 게이트는 규칙과 소형 모델로 처리해 LLM 호출을 추가하지 않는다.

### 5.5 컨텍스트 압축

알려진 L2 화면이면 DOM 전체 대신 화면 ID와 핵심 영역만 전달한다.

```text
[화면: 쇼핑몰 상품상세 #a3f2] 핵심: [가격][옵션][담기] / 무시됨: nav, footer, 추천, 광고
```

토큰이 줄고 LLM이 태스크 관련 영역에 집중한다. Engram에서 국소 패턴을 조회로 넘겨 attention이 전역 문맥에 집중한 효과와 같은 방향의 가설이다.

### 5.6 확장 아이디어

- **의미 체크포인트**: "여기까지 완료" 상태를 화면 해시로 저장해 실패 시 마지막 확정 지점부터 재개한다.
- **부작용 지도**: L1에 결제·삭제·전송처럼 되돌릴 수 없는 클릭을 학습해 확인 절차를 자동 삽입한다.
- **사이트 개편 감지**: 도메인의 L2 적중률이 급락하면 개편 신호로 보고 해당 엔트리를 일괄 강등한다.
- **캐스케이드**: 소형 로컬 모델이 정적 판단을 맡고, 조회 실패 시에만 큰 모델을 호출한다.
- **공유 메모리**: 팀 단위로 공유하면 인기 사이트가 빠르게 채워진다. 단, 폼 입력값과 개인 페이지 내용은 저장하지 않고 구조 서명만 저장한다.

## 6. 실험 설계 제안

### 비교군

1. 순수 LLM 에이전트 (현재 기준선)
2. + L2 화면 메모리와 무시 영역 마스킹
3. + L1 요소 메모리와 게이트 폴백
4. + L3 흐름 메모리와 prefetch

### 측정 지표

| 지표 | 목적 |
|---|---|
| 태스크 성공률 | 조회가 정확도를 해치지 않는지 |
| 스텝당 LLM 호출 수, 입력 토큰 | 비용 절감 효과 |
| 스텝당·태스크당 지연 | prefetch와 호출 감소 효과 |
| 조회 적중률, 게이트 통과율, 폴백률 | 키 안정성과 게이트 품질 |
| 조회 처리 비율 대 성공률 곡선 | U자 최적점 존재 여부 |
| 사이트 개편 후 성공률 하락폭 | 낡은 지식의 위험 |

평가는 WebArena, Mind2Web류 벤치마크와 내부 시나리오를 함께 쓴다.

## 7. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 정규화가 강하면 다른 화면이 충돌하고 약하면 적중률이 0 | 관점별 정규화 강도를 달리한 멀티 키, 충돌 로그 |
| 확신도 높은 엔트리가 낡아 조용히 오작동 | 실행 후 예측 대조, 확신도 즉시 감쇠, 개편 감지 |
| 조회 비율이 높아 새로운 상황에 취약 | 조회 비율 상한과 U자 곡선 측정 |
| 개인정보가 메모리에 유입 | 구조 서명만 저장, 입력값·개인 콘텐츠 제외 |
| 공유 메모리 포이즈닝 | 출처·서명 검증, 격리된 개인 메모리 우선 |
| 기존 접근과 차별성 부족 | Voyager식 skill library, Agent Workflow Memory와 비교해 정규화 키·게이트·prefetch의 기여를 분리 측정 |

## 8. 최종 판단 및 다음 액션

Engram의 교훈은 "브라우저 에이전트의 매 스텝을 LLM 추론으로 처리하지 말고, 반복되는 정적 판단은 저장해 두고 검증하며 꺼내 쓴다"는 것이다. 모델 학습 없이 시스템 계층에서 시도할 수 있고, 조회 비율·비용·성공률의 관계를 측정할 수 있어 실험 가치가 있다.

권장 다음 액션은 다음과 같다.

1. 현재 agent의 DOM/접근성 트리를 role 기반으로 정규화하는 함수와 L2 화면 해시 키 스키마를 정의한다.
2. 기존 실행 로그로 화면 해시 적중률을 오프라인으로 먼저 측정한다.
3. 무시 영역 마스킹만 적용한 최소 버전으로 토큰 절감과 성공률 변화를 확인한다.
4. 게이트 폴백을 붙인 L1 요소 메모리로 확장하고 조회 비율 대 성공률 곡선을 그린다.
5. 효과가 확인되면 L3 흐름 메모리와 prefetch를 추가한다. 자체 소형 모델에 Engram 모듈을 넣는 방향은 데이터와 학습 비용이 커서 가장 마지막에 검토한다.
